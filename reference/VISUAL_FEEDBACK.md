# Owner visual feedback

This feedback supersedes the initial visual proposals wherever they conflict. Source: the owner's follow-up in the preproduction discussion after reviewing the starter package.

> Out of these views, the combat view is the only view I like for how the game could look in concept. I want to render each combat in scene of the surrounding area. So this is a perfect example of what those could look like.. Those sprites look great though we need to animate both idle animations and idle emissive effects and emotes that the sprite can randomly cycle through while we are in combat. I want to make this project a github repo attached to https://github.com/GetFluxxed/MagiSprite.git

## Recorded decisions

- **Approved visual reference:** the combat view, including its in-scene Sprite appearance.
- **Not approved as visual directions:** the standalone Sprite sheet, Mage sheet, exploration view, Sprite Book view, progression view, and bonding modal. Preserve them as historical studies only.
- **Required scene relationship:** each combat is rendered in the surrounding area's setting.
- **Required combat presentation:** Sprite idle animations, idle emissive effects, and emotes that cycle randomly while in combat.
- **Repository destination:** [GetFluxxed/MagiSprite](https://github.com/GetFluxxed/MagiSprite).

The feedback approves a concept direction, not final art, animation timings, rendering technology, the entire proposed fiction, or the combat mockup's example mechanics. Those details still need design work or confirmation through testing.
